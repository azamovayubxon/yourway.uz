# yourway.uz

Платформа профориентации и жизненного планирования для Узбекистана (UZ/RU): психологические тесты и опрос, по которым ИИ составляет персональный маршрут из точки А в точку Б.

- Инструкция для Claude Code: [`CLAUDE.md`](CLAUDE.md)
- План этапов и чек-листы: [`docs/PLAN.md`](docs/PLAN.md)
- Чек-лист перед запуском для настоящих пользователей: [`docs/launch-checklist.md`](docs/launch-checklist.md)
- Документы продукта: [`docs/`](docs/)
- Тесты и опрос (JSON): [`data/tests/`](data/tests/)

## Стек

Next.js (App Router) + TypeScript, Tailwind CSS, PostgreSQL + Prisma, Vitest. Хостинг: Vercel + Neon
(проект переносимый: без функций, которые работают только на Vercel — см.
[`docs/deploy-server.md`](docs/deploy-server.md), как развернуть на обычном Linux-сервере через
Docker или напрямую).

## Как запустить у себя

Нужны Node.js 22 и PostgreSQL.

```bash
npm install              # установить зависимости (заодно сгенерируется клиент Prisma)
cp .env.example .env     # создать файл настроек и вписать строку подключения к базе
npm run db:deploy        # применить миграции базы
npm run dev              # запустить сайт на http://localhost:3000
```

Проверка, что сайт видит базу: открыть http://localhost:3000/api/health — должно быть `{"ok":true,"db":"ok"}`.

## Прохождение тестов и опроса

- `/start` — экран-развилка «знаю цель / не знаю». Выбор создаёт анонимную сессию (её id хранится в cookie `yw_session`).
- `/test` — 4 теста подряд, один вопрос на экран. Каждый ответ сразу сохраняется в базу. Если связи нет, ответы ждут в памяти браузера и отправляются, когда связь появится.
- Когда отвечены все 110 вопросов, сервер считает баллы и сохраняет их в сессии (статус `tests_done`).
- `/survey` — контекстный опрос сразу после тестов: «О вас» → «Ресурсы» → «Цель» (блок «Цель» — только у пути «знаю цель»). Вопрос `path_type` не повторяется — он уже задан на развилке. Автосохранение и продолжение с места обрыва — как в тестах.
- Когда отвечены все вопросы опроса для этого пути, сервер собирает профиль (Приложение А §9) и сохраняет его в сессии (статус `survey_done`).
- После опроса сразу открывается `/teaser`: экран «Анализируем ваш профиль…», затем бесплатный тизер (см. ниже).
- `/dev/profile/<id сессии>` — посчитанные баллы и собранный профиль. Открывается локально и на превью-ссылках Vercel, на боевом сайте (`VERCEL_ENV=production`, а вне Vercel — `NODE_ENV=production`) отдаёт 404.

## ИИ-тизер

- `/teaser` показывает экран генерации и сам запускает её (`POST /api/teaser` отвечает сразу, генерация идёт в фоне через `after()`), затем раз в 3 секунды спрашивает статус (`GET /api/teaser`). Тизер сохраняется в таблице `Teaser`, повторно не генерируется: перезагрузка страницы показывает тот же тизер.
- **Тестовый режим ИИ.** Если `ANTHROPIC_API_KEY` не задан (или `AI_MODE=mock`), вместо Claude отдаётся golden example из Приложения Б §9 (на узбекском — тот же пример, написанный по-узбекски). Вверху видна плашка «тестовый режим ИИ». Вся воронка проходится без ключа.
- **Настоящий ИИ.** Задать `ANTHROPIC_API_KEY` (и `AI_MODE=live` или убрать `AI_MODE`). Модель — `MODEL_TEASER` для русского и `MODEL_TEASER_UZ` для узбекского.
- **Узбекский.** К промпту добавляется блок правил на узбекском, глоссарий (`docs/uz-glossary.md`) и эталонные тексты (`docs/uz-teaser-examples.md`). Ответ проверяется на кириллицу, «Tu», формы на «sen», английские слова и запрещённые конструкции (`src/lib/ai/uz-style.ts`); если что-то найдено — повтор. Подробнее — `docs/uz-style.md`.
- Ответ ИИ проверяется схемой и правилами (все поля, 2–3 направления, нет сумм и заглушек, текст на нужном языке; для узбекского — ещё и проверка стиля). При провале — 1 повтор, в котором ИИ получает свой прошлый ответ и список проблем; затем понятное сообщение и кнопка «Попробовать ещё раз». Вся генерация укладывается в 100 секунд.
- `/dev/ai-log` — служебная страница (не работает на боевом сайте): последние 30 вызовов ИИ (тизеры и части полных отчётов) (время, язык, модель, длительность, принят/брак, что не прошло проверку, текст ответа) и средняя длительность тизера по языкам, а также время и стоимость последних полных отчётов. Та же сводка (без текста ответов) доступна админам всегда, в том числе на боевом сайте: `/admin/ai-log`.
- Каждый вызов ИИ пишется в таблицу `AiCall` (модель, токены, примерная стоимость в $, время) и одной строкой `[ai] teaser ...` в лог сервера.
- Лимиты — в `.env` (`TEASER_LIMIT_PER_SESSION`, `TEASER_LANG_REGEN_PER_SESSION`, `TEASER_LIMIT_PER_IP_PER_DAY`).
- Тизер остаётся на языке, на котором был составлен. Если переключить язык, рядом появится кнопка «Составить портрет на … языке» (тратит `TEASER_LANG_REGEN_PER_SESSION`).
- Если в профиле `answer_quality = low`, под карточкой типа мягкая подсказка пройти тесты ещё раз.
- `/dev/quick-start` — служебная ссылка (не работает на боевом сайте): создаёт новую сессию со случайными ответами и сразу открывает тизер. Параметры: `?path=knows_goal` / `?path=no_goal`, `?flat=1` — все ответы одинаковые (проверка подсказки о неточном результате). Если что-то сломалось, показывает страницу с текстом ошибки (не белый экран). Для массовой проверки тизеров на превью поднимите `TEASER_LIMIT_PER_IP_PER_DAY` в настройках Vercel для окружения Preview: иначе после 30 тизеров за сутки с одного IP сработает лимит.

## Аккаунт

- Регистрация появляется только перед оплатой: кнопка «Открыть полный отчёт» на тизере ведёт на `/register` (без аккаунта). В шапке есть только «Войти» — для тех, у кого аккаунт уже есть.
- Нужны только логин и пароль. Логин — латиница, цифры, `.`, `_`, `-` (3–32 символа), регистр не важен. Пароль — от 8 символов. Пароль и код восстановления хранятся только в виде хеша argon2id.
- После регистрации один раз показывается **код восстановления** (`XXXX-XXXX-XXXX-XXXX`): его можно скопировать или скачать файлом. «Продолжить» активна, только когда человек отметил, что сохранил код.
- `/recover` — «Забыли пароль?»: логин + код + новый пароль. После этого старый код перестаёт работать, выдаётся новый (тоже один раз), а все прежние входы на других устройствах закрываются.
- Анонимная сессия тестов при регистрации или входе привязывается к аккаунту: ответы, профиль и тизер остаются. При входе с другого устройства открывается последняя сессия аккаунта. После выхода сессия в браузере «забывается»: следующий человек за этим устройством чужой портрет не увидит.
- Вход хранится в cookie `yw_auth` (90 дней), в базе — только хеш токена (таблица `AuthSession`).
- **Защита от перебора:** после `AUTH_MAX_FAILURES` (5) неудачных попыток входа или восстановления в один логин вход в него закрывается на `AUTH_LOCK_MINUTES` (15) минут; с одного IP — не больше `AUTH_MAX_FAILURES_PER_IP` (50) неудач за то же время; не больше `AUTH_REGISTER_PER_IP_PER_HOUR` (20) новых аккаунтов с IP в час. Попытки пишутся в таблицу `AuthAttempt` (логин и хеш IP).

## Оплата и полный отчёт

- После регистрации (или входа) с тизера человек сразу попадает на `/checkout` — выбор уровня. Оба уровня доступны всем; подходящий по развилке выделен как рекомендуемый (`knows_goal` → «Маршрут», `no_goal` → «Навигатор»).
- **Цены — в базе** (таблица `Price`), стартовые: «Маршрут» 29 000 сум, «Навигатор» 79 000 сум. Их видно на `/checkout`, на лендинге и на `/pricing`. Менять — в админке: `/admin/prices`.
- **Промокоды** — таблица `PromoCode` (скидка 1–100 %, можно ограничить число использований и срок). Промокод на 100 % открывает отчёт сразу, без оплаты. Управление — в админке: `/admin/promo` (там же видны и тестовые коды, если такие остались).
- **Тестовая оплата** (провайдер `test`): страница «Тестовая оплата» с кнопками «Оплатить», «Имитировать отказ банка», «Отменить». Включается **только** если `PAYMENTS_TEST_MODE=true` **и** это не боевой сайт (на Vercel — `VERCEL_ENV` не `production`; вне Vercel — `NODE_ENV` не `production`). Даже если переменную по ошибке включат для Production, на боевом сайте тестовая оплата не заработает. Настоящие Payme, Click, Uzum — этап 9 (интерфейс `PaymentProvider` в `src/lib/payments/providers.ts`).
- В таблице `Payment` хранятся только id транзакции, сумма, валюта и статус (`pending` / `paid` / `cancelled` / `failed`). Данных карт у нас нет.
- **Генерация полного отчёта — в фоне и по частям** (Приложение Б §5а): 1) портрет и цель, 2) главный маршрут, 3) обучение, будущее, альтернативы, первые шаги. Страница отчёта раз в 3 секунды спрашивает `POST /api/report/<id>`; сервер отвечает сразу и, если никто не генерирует, запускает в фоне (`after()`) одну попытку следующей части. Каждая попытка — отдельный запрос, укладывается в `maxDuration = 300` с (лимит Vercel Hobby/Pro с Fluid compute); на своём сервере лимита нет. Статус хранится в базе: `pending` → `generating` → `ready` / `failed`.
- Системный промпт у всех частей один (для каждого языка) и кэшируется (prompt caching). Модель — `MODEL_ROUTE` («Маршрут») или `MODEL_NAVIGATOR` («Навигатор»), `effort: medium`.
- Каждая часть проверяется схемой и правилами: обязательные поля по типу пути (решение (З)), 1–2 альтернативы, сроки и суммы с пометкой «ориентировочно», нет заглушек, русский — только «вы», узбекский — проверка стиля как у тизера (нет кириллицы, «sen», английских слов, запрещённых конструкций). При провале — 1 повтор с подсказкой; если и он не прошёл — сообщение и кнопка «Сгенерировать заново» (бесплатно, готовые части не пишутся заново).
- Отчёт видит только владелец аккаунта: без входа — страница входа, чужой отчёт — 404. Список отчётов — в `/account`.
- **Имитация сбоя ИИ:** `/dev/ai-fail` (не работает на боевом сайте) — включить, оплатить отчёт, увидеть сообщение о сбое, выключить, нажать «Сгенерировать заново».

## Админка

- `/admin` — панель для администраторов (роли `admin`/`superadmin`, поле `role` в таблице `User`). Интерфейс — только на русском. Раздел не значится нигде на сайте: и без входа, и обычному пользователю `/admin/**` отдаёт обычную 404 (чтобы не палить, что раздел вообще есть).
- **Как стать суперадмином (без единого SQL-запроса).**
  1. Зарегистрируйте обычный аккаунт на сайте (логин и пароль) — как любой пользователь, через `/register`.
  2. В Vercel: Settings → Environment Variables → добавьте `SUPERADMIN_LOGINS` со значением этого логина (несколько логинов — через запятую, без пробелов: `owner,ozod`). Локально — впишите то же в `.env`.
  3. Перезапустите сайт (на Vercel переменные окружения подхватываются со следующим деплоем; локально — перезапустите `npm run dev`) и войдите в аккаунт. Готово: `/admin` открывается, а роль показывается как «суперадмин».

  Суперадмины из этой переменной действуют всегда, даже если в базе у аккаунта `role = "user"`, и их нельзя понизить из самой админки — так владелец не может случайно закрыть себе доступ.
- **Обычных администраторов** назначает суперадмин прямо в `/admin/admins` — по логину, без переменных окружения и без SQL. Роль хранится в базе (`User.role`).
- Разделы:
  - `/admin/prices` — цены уровней «Маршрут» и «Навигатор» (таблица `Price`).
  - `/admin/promo` — промокоды: создать, включить/выключить, удалить (сюда же переехал `/dev/promo`).
  - `/admin/prompts` — модель ИИ по уровню и языку (переопределяет `.env` без деплоя, хранится в таблице `ModelOverride`) и тексты промптов для справки (сами промпты по-прежнему редактируются в коде — `src/lib/ai/prompts.ts`, — автотест сверяет их с `docs/prilozhenie-b-prompty.md`).
  - `/admin/reports` — список оплаченных отчётов и просмотр содержимого каждого (профиль, тизер, собранный отчёт, стоимость генерации).
  - `/admin/analytics` — воронка по шагам (заход → старт теста → конец теста → тизер → регистрация → оплата → PDF) с разбивкой по языкам.
  - `/admin/ai-log` — себестоимость ИИ: журнал вызовов, токены, стоимость (то же, что `/dev/ai-log`, но доступно админам и на боевом сайте).
  - `/admin/admins` (только суперадмин) — кто ещё администратор.
- «Заход на сайт» и «скачали PDF» в воронке считаются по таблице `FunnelEvent` (заход — не чаще раза в сутки на посетителя, через cookie `yw_seen`); остальные шаги — напрямую по `TestSession`, `Teaser`, `User`, `Payment`.

## Языки

К пользователю сайт обращается только на «вы» (узбекский — только «siz»), см. CLAUDE.md §10 (О).

Язык хранится в cookie `locale`. Новому посетителю показывается язык из `DEFAULT_LOCALE` (по умолчанию `uz`).
В узбекских текстах буквы `oʻ gʻ` пишутся знаком `ʻ` (U+02BB), апостроф внутри слова (`taʼlim`) — знаком `ʼ` (U+02BC). Автотест проверяет, что в словаре нет обычных апострофов.
