## Что не входит в эту сессию

- Правка формулировок вопросов теста и шкал (UZ_COPY §2–3) — сделана в отдельной сессии после решения владельца по `test-wording-review.csv` (см. UX-04 выше).
- Переписывание сгенерированных рекомендаций ИИ (UZ_COPY §7: категоричные выводы, стиль обучения как способность, скорректированные проценты) — правка промптов, не безопасная UI-замена; требует отдельной сессии с проверкой автотеста сверки промптов с документом.
- Полная перестройка главной, тестового прогресса, тизера, чекаута и кабинета (этап B) и контракт данных для генерации + реальные источники возможностей (этап C) — по прямому указанию не начинались.

### 3. Старт и тест (ТЗ §6)

- Экран-развилка (`/start`): тексты без изменений по содержанию, кнопки выбора — на токенах (`border-line`, `focus-ring`, минимум 96 px высоты).
- Новый экран подготовки — часть `TestRunner` (`prepDismissed` состояние): 4 блока теста, что дальше, «нет правильных ответов», объяснение автоперехода, честная подпись о сохранении, кнопка «Начать тест». Показывается только при полностью пустой сессии — при возврате/резюме пропускается.
- Компактный прогресс `1/4 · Личность` + `16/60` (номер вопроса **внутри блока**, не сквозной) и отдельная строка-путь «Тест → Анкета → Результат» (`StageBreadcrumb`) — не конкурируют с общим прогресс-баром.
- Промежуточные экраны между блоками (`atBoundary`): короткий текст «Раздел ... завершён. Теперь...» и одна кнопка «Продолжить», без конфетти. Не показываются повторно при обычной навигации «Назад» внутри уже пройденного блока.
- Фокус после ответа переставляется на заголовок нового вопроса (`tabIndex=-1` + `ref.focus()`), а не остаётся на кнопке прежнего ответа. Кнопки ответа блокируются (`disabled`) на время короткой паузы автоперехода — защита от двойного нажатия.
- Статусы сохранения — по факту (`SaveStatus`): «Сохраняем…» пока есть неотправленные ответы, «✓ Сохранено» когда всё подтверждено сервером, «Не удалось сохранить.» + кнопка «Повторить» при обрыве связи.
- Кнопка «Пауза» открывает честную подпись: ответы уже сохранены на сервере, продолжить можно на этом же устройстве и в этом же браузере; без аккаунта — с другого устройства нельзя (без ложных обещаний синхронизации).
- Внутри `/test` и `/survey` — сокращённый footer (`FooterGate`, по `pathname`): только «Часто задаваемые вопросы» и «Политика конфиденциальности» + почта, без полной маркетинговой навигации.

### 4. Анкета (ТЗ §6)

- Подписи полей: заголовок вопроса связан с полем через `aria-labelledby` (числовое поле возраста, текстовые поля, группы вариантов) — исправляет находку аудита про `spinbutton` без имени.

- Текстовые поля (навыки, увлечения): плейсхолдер-пример и счётчик символов «{n} из {max}».
- Вопрос о поле — оставлен (не убирали), рядом добавлено объяснение зачем нужен, с явным «Не указывать» как и раньше.
- Границы бюджета и времени сделаны однозначными: `5 mln so'mgacha` → `5 mln so'mdan ko'p — 20 mln so'mgacha` → `20 mln so'mdan ko'p — 50 mln so'mgacha` → `50 mln so'mdan ko'p` (аналогично для часов в неделю и желаемого дохода). **Менялись только `label_ru`/`label_uz` в `context_survey.json`, значения (`value`, `maps_to`) не трогали** — старые профили и подсчёт не затронуты.
- **Город/регион не добавляли** — это самостоятельное решение владельца (новое поле в анкете и в модели профиля), не безопасная правка формулировок. Нужно решить: (1) не собирать вообще (как сейчас; локальные рекомендации будут общими по стране), (2) добавить необязательное поле «город» в анкету, влияющее на профиль и, возможно, в mapsTo `demographics.city`, — но тогда это меняет схему профиля (Приложение А §9) и требует отдельного решения по обратной совместимости старых профилей без этого поля.
- Новый экран «Проверьте ваши условия» перед генерацией (`SurveyRunner`, после последнего вопроса): бюджет, время в неделю, языки, готовность к переезду и цель (или честная подпись «цель ещё не выбрана» для `no_goal`) — с кнопкой «Изменить» у каждого поля, переносящей обратно к нужному вопросу. Подтверждение («Всё верно, продолжить») запускает переход к тизеру.

### 5. Критическая находка вне рамок B1 — СРОЧНО

**CSP (`next.config.ts`, `script-src 'self'`, этап 10А) блокирует собственные inline-скрипты Next.js, из-за чего ни одно взаимодействие на клиенте не работает нигде на сайте** — ни в `next dev`, ни в собранном `next build && next start` (проверено оба раза). Пример: на `/test` клик по варианту ответа не отвечает на вопрос — совсем никак, вопрос остаётся тем же. Консоль показывает `Refused to execute inline script ... script-src 'self'`, следом — `Minified React error #412` (гидратация). Воспроизведено **и на исходном коде до этой сессии** (проверено через `git stash` на коммите `132c598`) — это не следствие правок B1, а существующий баг, скорее всего с момента коммита `fdb0cc4` («Этап 10А: безопасность»). Проверка B1 в браузере поэтому не могла пройти кликами: пришлось верифицировать через SSR (прямые ссылки и заполнение сессии в БД по `/dev/quick-start` и напрямую) — все новые экраны рендерятся корректно (см. скриншоты `question-*.png`, `seed-*.png`, `survey-gender-uz-390.png`, `survey-langs-uz-390.png`), но **ни один клик сейчас не работает у реальных пользователей** — ни в тестах, ни в опросе, ни где-либо ещё. Это отдельная срочная задача (не B1, не UX) — подробнее в отчёте сессии; заведена как предложенная задача.
