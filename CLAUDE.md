# yourway.uz — инструкция для Claude Code

Этот файл Claude Code читает в начале каждой сессии. Здесь всё, что нужно знать о проекте, и правила работы.

---

## 1. С кем ты работаешь

- Владелец проекта (Аюбхон) **не программист**. Он ставит задачи словами, проверяет результат в браузере и принимает продуктовые решения.
- Общайся **по-русски**, простыми словами, без жаргона. Если без термина не обойтись, объясни его одной фразой.
- В конце каждой задачи дай короткий отчёт:
  1. **Что сделано** (3–6 пунктов, человеческим языком).
  2. **Как проверить**: какую страницу открыть, что нажать, что должно получиться.
  3. **Что дальше**: следующий этап или то, что нужно от владельца (ключ, решение, текст).
- Продуктовые решения (цены, состав тестов, тексты промптов, логика тизера, что бесплатно и что платно) **уже приняты** в документах в `docs/`. Не меняй их сам. Если документы противоречат друг другу или чего-то не хватает, **спроси**, предложив 2–3 варианта и отметив рекомендуемый.
- Работай **по одному этапу** из раздела 9. Не забегай вперёд и не добавляй функции «на будущее», которых нет в этапе.

## 3. Стек (решено)

- **Next.js (App Router) + TypeScript**: одно приложение, где есть и страницы, и API.
- **Tailwind CSS**. Вёрстка **mobile-first**: всё должно нормально работать на экране шириной 375px и на слабом Android.
- **PostgreSQL + Prisma**. Если в среде разработки Postgres поднять нельзя, для разработки допустим SQLite, но схема должна оставаться совместимой с Postgres.
- **i18n: `uz` (латиница) и `ru`**. Все строки интерфейса лежат в словарях, а не в коде. Переключатель UZ/RU есть на каждой странице, выбор запоминается в cookie. Язык по умолчанию задаётся в `DEFAULT_LOCALE` (по умолчанию `uz`). Узбекские буквы `oʻ gʻ` должны отображаться корректно везде, включая PDF.
- **Claude API** через `@anthropic-ai/sdk`. ID моделей не хардкодить, брать из конфига или переменных окружения:
  - тизер: `MODEL_TEASER` (по умолчанию `claude-haiku-4-5`);
  - отчёт «Маршрут»: `MODEL_ROUTE` (по умолчанию `claude-sonnet-5`);
  - отчёт «Навигатор»: `MODEL_NAVIGATOR` (по умолчанию `claude-opus-5-5`).
  Для неизменной части системного промпта включить **prompt caching**.
- **Мок-режим ИИ.** Если `ANTHROPIC_API_KEY` не задан, приложение работает в режиме `AI_MODE=mock` и возвращает golden example из Приложения Б §9 (для полного отчёта — правдоподобную заглушку по той же схеме). Вся воронка должна проходиться от начала до конца **без ключа**. В интерфейсе в мок-режиме показывать маленькую плашку «тестовый режим ИИ».
- **Тесты кода:** Vitest. Движок подсчёта баллов покрыт тестами обязательно.
- **Хостинг:** Vercel (превью-ссылка на каждый push) + Postgres от Neon. Приложение должно оставаться **переносимым**: без функций, которые работают только на Vercel, чтобы потом можно было переехать на хостинг в Узбекистане.
- Секреты **никогда** не пишутся в код и не коммитятся. Все переменные перечислены в `.env.example` с комментариями на русском.

## 4. Данные тестов: как использовать

- Вопросы, варианты и ключи **загружаются из `data/tests/*.json`**. Тексты не перепечатывать вручную.
- Все ответы на тесты по шкале Ликерта 1–5. Подписи шкалы берутся из `scoring.response_scale` каждого файла.
- Подсчёт выполняет **детерминированный код на сервере, без ИИ** (Приложение А §3–§6):
  - **Big Five** (`ipip_neo_60_short.json`): для обратных пунктов балл = `6 − ответ`. По 12 пунктов на шкалу, raw 12–60, `pct = round((raw − 12) / 48 × 100)`.
  - **RIASEC** (`riasec_30.json`): сумма по 6 типам, код = топ-3 по убыванию. При равенстве сумм порядок R→I→A→S→E→C. Правило ничьих задокументировать в коде.
  - **Ценности** (`values_12.json`): сумма по 6 ценностям, отсортированная по убыванию.
  - **Восприятие** (`perception_8.json`): стиль с максимальной суммой. Если разница с ближайшим ≤ 1 балла, вернуть топ-2.
  - **16-тип** (`bigfive_to_16type_mapping.json`): порог 50. **Ровно 50 уходит в low pole** (I, S, T, P), как указано в mapping-файле. Если |pct − 50| ≤ 5, отмечать ось как слабо выраженную только во внутренних данных.
- ⚠️ **Важный нюанс Big Five.** Блок `interpretation.scales` в `ipip_neo_60_short.json` перенесён из 120-пунктовой версии: там `item_count: 24`, `raw_range` и перцентили в диапазоне 20–100. К формуле для 60 пунктов это **не подходит**. Кроме того, тексты написаны HR-языком («кандидат», «сотрудник», «рекомендации по найму»). Правила:
  - уровень шкалы считать по `pct` третями: 0–33 низкий, 34–66 средний, 67–100 высокий;
  - `raw_range` и `percentile_range` из этого блока **не использовать**;
  - HR-тексты **не показывать пользователю** и не передавать в ИИ. В профиль идут только проценты.
- Порядок в воронке (Приложение А §11): экран-развилка (`path_type`) → Big Five (60) → RIASEC (30) → Ценности (12) → Восприятие (8) → Контекстный опрос → генерация → тизер.
- Опрос строится из `context_survey.json`: поле `maps_to` задаёт, в какое поле профиля пишется ответ, `show_if` задаёт условный показ. Вопрос `path_type` уже задан на экране-развилке, поэтому в опросе его пропускать.
- Итоговый профиль должен **точно** соответствовать структуре из Приложения А §9.

## 5. UX воронки

- Один вопрос на экран (для Ликерта: крупные кнопки 1–5 с подписями и автопереход к следующему вопросу), прогресс-бар, кнопка «Назад».
- **Автосохранение**: анонимная сессия (id в cookie), ответы пишутся в БД сразу. При перезагрузке или обрыве связи человек продолжает с того же места.
- Тесты проходятся **до** регистрации и оплаты. Регистрация появляется только перед оплатой.
- Экран генерации: «анализируем твой профиль…» с анимацией, ожидание до ~40 сек.

---

## 6. Приватность и аккаунт

- ФИО, телефон и e-mail **не собираются**. Аккаунт состоит из логина и пароля (хеш argon2 или bcrypt).
- При регистрации один раз показывается **код восстановления**, который пользователь сохраняет сам. В БД хранится только его хеш.
- Ограничение попыток входа (защита от перебора).
- Пользователь может удалить аккаунт вместе с данными.

---

## 7. ИИ-генерация (Приложение Б)

- Тексты промптов переносятся из Приложения Б **дословно** в отдельный модуль (позже их можно будет редактировать в админке с версиями).
- Два вызова:
  1. **тизер** (бесплатный, до оплаты);
  2. **полный отчёт** (только после оплаты; на вход идут профиль и JSON тизера).
- Ответ ИИ — строго JSON. Проверять схемой (zod) и правилами из Приложения Б §8. При провале — до 2 повторов, затем понятное сообщение пользователю. **Оплаченный доступ при сбое никогда не теряется**: отчёт можно перегенерировать без повторной оплаты.
- Для каждого вызова логировать модель, токены и примерную стоимость.
- **Лимит на генерацию тизера** (по сессии и по IP): тизер бесплатный, а стоит денег.
- Язык генерации = язык интерфейса пользователя.

## 8. Оплата

- Уровни и стартовые цены: «Маршрут» 29 000 сум, «Навигатор» 79 000 сум. Цены хранятся в БД, а не в коде.
- Архитектура: интерфейс `PaymentProvider`, под ним Payme, Click, Uzum.
- До подключения реального шлюза работает провайдер `test`, который включается только при `PAYMENTS_TEST_MODE=true`, плюс промокоды (в том числе 100%). Так владелец может пройти оплату и увидеть отчёт.
- Данные карт **никогда** не хранятся у нас. Храним только id транзакции, сумму и статус.

## 9. План этапов

Каждый этап — отдельная сессия. Этап готов, когда: проект собирается, тесты проходят, всё работает на ширине 375px и на обоих языках, изменения закоммичены и запушены, владелец получил отчёт по форме из раздела 1.

1. **Каркас.** Next.js + TS + Tailwind + Prisma, i18n UZ/RU с переключателем, лендинг по ТЗ 3.1.1 (тексты-заглушки, которые легко заменить), заглушки статических страниц (как это работает, цены, FAQ, оферта, политика), `.env.example`, README «как запустить», готовность к деплою на Vercel.
2. **Тесты и подсчёт.** Модель `TestSession`, экран-развилка, прохождение 4 тестов из JSON с автосохранением, движок подсчёта с тестами Vitest (обратные пункты, ничьи, 16-тип, крайние значения). Страница `/dev/profile/[id]` (доступна только вне production) показывает посчитанные баллы.
3. **Опрос и профиль.** Контекстный опрос с `show_if` и `maps_to`, сборка профиля по Приложению А §9, сохранение в БД, отображение на `/dev/profile/[id]`.
4. **ИИ-тизер.** Модуль промптов, мок-режим, вызов тизера с валидацией и повторами, экран генерации, страница тизера (портрет, сильные стороны, 2–3 направления, крючок-сюрприз, заблокированное оглавление с замками), лимиты, логирование токенов.
5. **Регистрация.** Логин и пароль, код восстановления, вход и выход, привязка анонимной сессии к аккаунту, защита от перебора.
6. **Оплата-заглушка и полный отчёт.** Выбор уровня, цены из БД, промокоды, провайдер `test`, генерация полного отчёта после оплаты, красивая онлайн-страница отчёта по всем блокам схемы, перегенерация без повторной оплаты.
7. **PDF и личный кабинет.** Брендированный PDF (кириллица и узбекская латиница), кабинет со списком отчётов, повторное скачивание, прохождение заново, смена пароля, удаление аккаунта.
8. **Админ-панель.** Роли admin и superadmin, цены, промокоды, промпты с версиями и выбором модели по уровню, просмотр отчётов, аналитика воронки (таблица событий: заход → старт теста → конец теста → тизер → регистрация → оплата → PDF), себестоимость ИИ на отчёт.
9. **Реальная оплата.** Payme, затем Click и Uzum. Делается только когда владелец даст данные мерчанта. Вебхуки, статусы, сверка. Фискализацию уточнить у владельца.
10. **Подготовка к запуску.** Проверка безопасности (XSS, CSRF, инъекции, rate limit), мониторинг ошибок, доступность, список узбекских текстов для вычитки носителем, юридические страницы (заготовки для юриста), чек-лист запуска.
